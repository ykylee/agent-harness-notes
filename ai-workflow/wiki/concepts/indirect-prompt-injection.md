# Indirect Prompt Injection — 이 부류 고유의 구조적 위험

- 문서 목적: 에이전트가 신뢰할 수 없는 콘텐츠를 읽을 때 생기는 공격면과, 실제로 구현된 완화책을 정리한다.
- 범위: 공격 사슬, 구조적 원인, 완화 4범주와 제품별 실태, 미해결 상태
- 성격: **실행 표면 고유의 축.** 다만 셸 하네스도 파일·웹 내용을 읽으면 같은 문제가 생긴다
- 최종 수정일: 2026-09-23

## §1 TL;DR  {#s1-tldr}

| # | 항목 | 값 |
|---|---|---|
| 1 | 성립 조건 | **로그인 세션 접근** + **신뢰할 수 없는 콘텐츠를 맥락으로 읽음** |
| 2 | 무력화되는 것 | **동일 출처 정책(SOP)** — 에이전트는 사용자 권한으로 출처를 가로지른다 |
| 3 | 사용자가 한 일 | **"이 페이지 요약해줘"를 누른 것뿐** |
| 4 | 2026 현재 | **해결되지 않았다.** OpenAI 자체 서술: "unlikely to ever be fully 'solved'" |
| 5 | 완화의 실질 | **권한 축소** — 민감 계정을 에이전트 브라우저에 로그인하지 않는 것 |

## §2 공격 사슬 (Brave 의 Comet 실증)  {#s2-chain}

| 단계 | 내용 |
|---|---|
| 1. 심기 | 페이지에 지시를 숨긴다 — "흰 배경의 흰 글자, HTML 주석, 기타 보이지 않는 요소". 또는 **Reddit 댓글 같은 사용자 생성 콘텐츠** |
| 2. 발동 | 사용자가 그 페이지에서 AI 를 부른다 — **"요약해줘"** |
| 3. 주입 | 시스템이 **사용자 지시와 신뢰할 수 없는 페이지 내용을 구분하지 않고** 처리 |
| 4. 실행 | AI 가 주입된 명령을 정당한 요청으로 취급 |
| 5. 탈취 | 실증: 이메일 주소 획득 → **Gmail 에서 OTP 추출** → 공격자 서버로 유출 → 계정 장악 |

## §3 구조적 원인  {#s3-cause}

> Comet 은 **"페이지의 일부를 사용자 지시와 웹페이지의 신뢰할 수 없는 내용을 구분하지 않고
> LLM 에 그대로 먹인다."**

입력 스트림이 하나로 합쳐지면 모델은 정당한 의도와 삽입된 페이로드를 구별할 수단이 없다.

> 📌 **이것이 [[concepts/perception-model]] 과 직결된다.** 무엇을 맥락에 넣는가를 정할 때
> **그것들의 신뢰 등급도 함께** 정해야 한다. 인식 설계와 보안 설계가 같은 결정이다.

## §4 완화 4범주 (Brave) 와 제품 실태  {#s4-mitigations}

| # | 범주 | 원문 요지 | 실제로 문서화한 제품 |
|---|---|---|---|
| 1 | **입력 분리** | "페이지 내용은 **항상 신뢰할 수 없는 것으로 취급**되어야 한다" | **Dia** (부분 — §5) |
| 2 | 출력 검증 | 모델 출력이 사용자 요청과 정합하는지 **독립 검사** | 조사 범위에서 미확인 |
| 3 | 보안 체크포인트 | 민감 동작은 **사용자 상호작용을 요구** | Aside, Dia ([[concepts/approval-gate]]) |
| 4 | 모드 격리 | 에이전틱 브라우징은 "inherently powerful-but-risky mode" — **우발적 활성화 방지** | Aside(시크릿 작업 모드), Dia |

> 📌 **가장 근본적인 #1 이 가장 덜 보인다.** #3·#4 는 여러 제품이 갖췄지만, 입력 계층에서
> 신뢰 등급을 가르는 것은 드물다.

## §5 Dia — 인식 계층에서의 방어  {#s5-dia}

조사 범위에서 **구체적 방어를 문서화한 유일한 제품**이다.

| 방어 | 원문 |
|---|---|
| LLM 생성 URL 추종 금지 | "Dia won't automatically open or follow LLM-generated URLs" |
| **URL 원문 전달 금지** | "Dia won't pass URLs to the LLM verbatim" |
| **민감 요소를 인식에서 제거** | 비밀번호 필드와 비가역 동작 버튼은 "**invisible to the agentic system**" |
| 초기 권한 최소 | 채팅은 "starts with **no access to other tabs** or ability to take write actions" |
| 자율 이동 금지 | 에이전트가 스스로 다른 사이트로 이동할 수 없다 |

그리고 **한계를 스스로 적는다** — 여전히 "tone shifts" 나 "nudge content toward misinformation"
은 가능하다.

> 📌 **방어를 나열하면서 무엇이 남는지도 적는 것**이 이 문서에서 가장 신뢰가 가는 부분이다.
> 완전 해결을 주장하지 않는다.
>
> 📌 "URL 을 LLM 에 원문으로 넘기지 않는다"와 "위험 요소를 인식에서 지운다"는 Brave 의 #1 과
> 완전히 같지는 않다 — 사용자 지시와 페이지 내용을 **구조적으로 가르는 것은 아니다**.
> 그러나 **인식에 들어가는 것을 통제**한다는 점에서 같은 층위다.

## §6 미해결 상태 (2026)  {#s6-unsolved}

| 사실 | 등급 |
|---|---|
| Atlas·Comet·Dia 에서 **프롬프트 주입은 완전히 패치될 수 없다**고 2026년 연구자들이 확인 | 📰 2차 |
| 2026-06 워싱턴대: 인기 에이전틱 브라우저 **7개 중 4개**에서 SOP 우회, Atlas 에 동작하는 데이터 탈취 PoC | 📰 2차 |
| OpenAI (2025-12): 프롬프트 주입은 **"unlikely to ever be fully 'solved'"** | 1차 인용(2차 경유) |
| **Atlas 종료 사유에 보안 유지보수 포함** | 📰 2차 |

### §6.1 벤더 반응을 최종 판정으로 삼지 말 것  {#s6-1-vendor}

| 사건 | 벤더 초기 반응 |
|---|---|
| CometJacking (Comet) | **보안 영향 부인** → 이후 독자 발견·패치 |
| Tainted Memories (Atlas) | **재현 가능성 반박** |
| Brave 의 Comet 주입 | 두 차례 수정 시도가 **모두 불완전** |

## §7 표면이 넓어질수록  {#s7-surface}

이 위험의 크기는 **에이전트가 닿을 수 있는 범위에 정비례**한다.

> ⚠️ Aside 의 `Computer Use` 는 시스템 전역 접근성 트리·이벤트 탭·화면 캡처·연락처에 닿는다
> ([[concepts/os-sandbox-policy]] §8.6). 속은 에이전트의 사정거리가 **브라우저 탭이 아니라
> 데스크톱 전체**가 된다.
>
> 📌 **"우리는 로컬이라 안전하다"는 주장과 프롬프트 주입은 별개 문제다.** 로컬 실행은 데이터
> 전송을 줄이지, 에이전트가 속는 것을 막지 않는다.

## §8 도입 판단에 쓸 정리  {#s8-practical}

- **"요약해줘" 한 번이 계정 장악으로 이어질 수 있는 위험을 받아들이는 것**이다
- 위험 수준은 그 브라우저가 **어떤 로그인 세션을 갖고 있느냐**에 정비례한다
- **완화의 실질은 권한 축소** — 민감 계정은 에이전트 브라우저에 로그인하지 않는 것이 가장 확실하다
- **승인 게이트를 끄지 마라.** 현재 실질적으로 작동하는 몇 안 되는 방어다
- 기업 도입이면 **관리형 정책의 도메인 블랙리스트**(Comet 의 managed storage 같은)를 확인하라
