# Harness Engineering — 자율 런타임을 통치하는 규율

- 문서 목적: OpenAI 내부 "손으로 쓴 코드 0" 실험에서 뽑힌 운영 원칙을 정리한다.
- 범위: 실험의 사실, 엔지니어 역할 재정의, legibility, 기계적 집행, 엔트로피와 GC, 적용 지침
- 1차 출처: [Harness engineering](https://openai.com/index/harness-engineering/), Ryan Lopopolo, 2026-02-11
- 최종 수정일: 2026-09-22

## §1 TL;DR  {#s1-tldr}

| # | 항목 | 값 |
|---|---|---|
| 1 | 실험 | 내부 베타 제품을 5개월간 **손으로 쓴 코드 없이** 출하 |
| 2 | 규모 | 약 **100만 줄**, 약 **1,500 PR**, 엔지니어 3명(현재 7명) |
| 3 | 처리량 | 엔지니어당 하루 **3.5 PR** — 팀이 커져도 *증가*했다 |
| 4 | 추정 | 손으로 했을 때의 약 **1/10 시간** |
| 5 | 표어 | **"Humans steer. Agents execute."** |
| 6 | 규율이 나타나는 곳 | 코드가 아니라 **scaffolding** |

## §2 병목은 모델이 아니라 환경이었다  {#s2-environment}

초기 진척은 기대보다 느렸다. Codex 가 무능해서가 아니라 **환경이 덜 명세돼 있어서**였다.

무언가 실패했을 때 답은 "더 열심히 해봐"가 아니라 늘:

> **"어떤 능력이 빠져 있고, 그것을 에이전트에게 어떻게 legible 하고 enforceable 하게 만들 것인가?"**

작업 방식은 **depth-first** — 큰 목표를 작은 구성 블록(설계·코드·리뷰·테스트)으로 쪼개고,
에이전트에게 그것을 짓게 하고, 그 블록으로 더 복잡한 과업을 연다.

리뷰는 거의 전부 **에이전트↔에이전트**로 밀렸다. Codex 가 자기 변경을 로컬에서 리뷰하고 → 로컬과
클라우드에 추가 리뷰를 요청하고 → 피드백에 응답하고 → 모든 에이전트 리뷰어가 만족할 때까지 반복.

## §3 애플리케이션을 에이전트에게 읽히게 만들기  {#s3-legibility}

코드 처리량이 오르자 병목은 **인간 QA 용량**이 됐다. 그래서 UI·로그·메트릭 자체를 Codex 가 직접 읽을
수 있게 만들었다.

| 조치 | 효과 |
|---|---|
| **git worktree 마다 부팅 가능**하게 | 변경마다 인스턴스 하나를 Codex 가 띄우고 조종 |
| **Chrome DevTools Protocol 을 에이전트 런타임에 배선** (DOM 스냅샷·스크린샷·내비게이션 skill) | 버그 재현, 수정 검증, UI 동작 추론 |
| 관측을 로컬 스택으로 노출, worktree 마다 ephemeral | 에이전트가 **LogQL 로 로그, PromQL 로 메트릭**을 질의 → "서비스 기동을 800ms 안에 끝내라" 같은 프롬프트가 성립 |

> 단일 Codex 실행이 한 과업을 **6시간 넘게** 붙들고 있는 일이 흔하다 (주로 사람이 자는 동안).

## §4 지도이지 설명서가 아니다  {#s4-map-not-manual}

> **"give Codex a map, not a 1,000-page instruction manual."**

"하나의 큰 `AGENTS.md`" 접근이 실패한 방식:

| # | 실패 양상 |
|---|---|
| 1 | **컨텍스트는 희소 자원이다** — 거대한 지시 파일이 과업·코드·관련 문서를 밀어낸다 |
| 2 | **지침이 너무 많으면 지침이 아니게 된다** — 전부가 "중요"하면 아무것도 중요하지 않다. 에이전트는 의도적으로 항해하는 대신 국소 패턴 매칭으로 빠진다 |
| 3 | **즉시 썩는다** — 단일 설명서는 낡은 규칙의 무덤이 되고 조용히 유혹적 위험물이 된다 |

> 팀을 아키텍처 패턴에 정렬시킨 그 Slack 논의? 에이전트가 발견할 수 없다면, 3개월 뒤 합류한 신입에게
> 알려지지 않은 것과 **같은 방식으로 illegible** 하다.

## §5 기계적 집행 — 지시가 아니라 불변식  {#s5-mechanical}

> **Enforce invariants; don't micromanage implementations.**

예: 경계에서 데이터 모양을 파싱하도록 **요구**하되, *어떻게* 할지는 규정하지 않는다.

계층 규칙 — 각 비즈니스 도메인 안에서 코드는 "앞으로만" 의존할 수 있다:

```
Types → Config → Repo → Service → Runtime → UI
```

횡단 관심사(auth, connector, telemetry, feature flag)는 **단일 명시 인터페이스: Providers** 로만
들어온다. 그 외는 금지이고, 커스텀 린터와 구조 테스트로 기계적으로 집행된다(물론 Codex 가 생성).

> **린트가 커스텀이므로 에러 메시지를 에이전트 컨텍스트에 교정 지시를 주입하도록 쓴다.**

> "이런 아키텍처는 보통 엔지니어 수백 명이 될 때까지 미룬다. 코딩 에이전트와 함께라면 **이른
> 전제조건**이다 — 제약이 있어야 부패 없는 속도가 나온다."

## §6 처리량이 머지 철학을 바꾼다  {#s6-merge}

- 차단성 머지 게이트 최소화
- PR 은 수명이 짧다
- 테스트 flake 는 무한 차단이 아니라 후속 실행으로 다룬다

> "에이전트 처리량이 사람의 주의력을 크게 넘어서는 체계에서는 **교정이 싸고 기다림이 비싸다.**"
> 낮은 처리량 환경에서는 무책임했을 선택이 여기서는 자주 옳다.

## §7 엔트로피와 GC  {#s7-entropy}

**Codex 는 저장소에 이미 있는 패턴을 복제한다** — 고르지 않거나 열등한 것까지. 드리프트는 불가피하다.

처음엔 사람이 수동으로 감당했다 — 매주 금요일(주의 20%)을 "AI slop" 정리에 썼고, 당연히 확장되지
않았다. 대신 **"golden principles"** 를 저장소에 직접 인코딩하고 반복 정리 프로세스를 지었다.

- 손으로 만든 헬퍼보다 공유 유틸리티 패키지를 선호 — 불변식을 중앙화
- 데이터를 "YOLO 식"으로 더듬지 않는다 — 경계를 검증하거나 타입 있는 SDK 에 의존해, 에이전트가
  추측한 모양 위에 짓지 못하게 한다

정기적으로 백그라운드 Codex 작업이 이탈을 스캔하고, 품질 등급을 갱신하고, 표적 리팩터링 PR 을 연다.
대부분 1분 안에 리뷰되고 자동 머지된다.

> 기술 부채는 고금리 대출과 같다 — 복리로 불려서 고통스럽게 몰아치는 것보다 **작게 계속 갚는** 편이
> 거의 언제나 낫다.

## §8 도달한 자율성 수준  {#s8-autonomy}

프롬프트 하나로 에이전트가 하는 일: 코드베이스 현재 상태 검증 → 보고된 버그 재현 →
**실패를 보여주는 영상 녹화** → 수정 구현 → 애플리케이션을 조종해 수정 검증 →
**해결을 보여주는 두 번째 영상 녹화** → PR 열기 → 에이전트·사람 피드백 응답 → 빌드 실패 감지·교정 →
판단이 필요할 때만 사람에게 에스컬레이션 → 머지.

> 저자는 이 동작이 **그 저장소의 구조와 도구에 크게 의존**하며 비슷한 투자 없이 일반화된다고 가정해선
> 안 된다고 명시한다.

## §9 내 프로젝트에 옮기기  {#s9-applying}

| 원칙 | 행동 |
|---|---|
| 설명서가 아니라 지도 | `AGENTS.md` / `CLAUDE.md` 를 100줄 안팎의 목차로 유지하고 깊이는 `docs/` 로 밀어낸다 |
| 기계적 집행 | 문서 신선도와 상호링크를 CI 에서 린트. **에러 메시지에 교정 지시를 담는다** |
| 계획을 1급 산출물로 | 진행/완료/기술부채 계획을 저장소에 커밋 |
| 앱을 에이전트에게 legible 하게 | worktree 단위 부팅, 로그/메트릭 질의 경로, 브라우저 제어 skill |
| 지시가 아니라 불변식 | 계층 의존 방향을 집행하되 라이브러리 선택은 자유 |
| 지속적 GC | 드리프트를 스캔하고 표적 PR 을 여는 주기적 백그라운드 작업 |
| 컨텍스트를 저장소로 | 채팅·문서 도구에 사는 결정을 저장소의 버전 관리 산출물로 이관 |

## §10 하네스는 성능 변수다  {#s10-perf-variable}

"Codex as a platform" 포스트의 직접 진술:

> "Harness design can materially change results: on ARC-AGI-3, retained reasoning and context
> compaction raised GPT-5.6 Sol's score from 13.3% to 38.3% while reducing output tokens sixfold."

**모델 교체가 아니라 두 개의 하네스 수준 설정**이다. 자세한 것은 [[concepts/retained-reasoning]].
